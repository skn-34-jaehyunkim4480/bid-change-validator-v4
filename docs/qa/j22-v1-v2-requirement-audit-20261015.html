3. 면허제한 API와 원문의 불일치

v1 구조화 면허제한은 동일 lmtGrpNo=1에 1261, 1262가 들어 있었고, v2에서는 1261: group 1, 1262: group 2로 분리됐습니다. 현재 엔진은 그룹 간 OR, 그룹 내부 AND로 해석합니다. 그 결과 v1의 요건 행은 1개이고 v2는 OR 요건 2개입니다.

다만 두 차수 공고문에 모두 업종 종합여행업[1261] 또는 국내외여행업[1262]이 명시돼 있어, 문서 원문과 v1 API 그룹 구성은 충돌합니다. 이를 사용자에게 'v1은 두 면허를 모두 보유해야 한다'는 확정 사실로 표현하면 안 됩니다. v1은 충돌을 확인 필요로 남기는 것이 안전하며, 운영 DB의 그룹 값을 임의 변경하지 않았습니다.

4. 핵심 결함: 제안서 실적 평가를 참가 필수요건으로 취급

추가 검토·코드 개선 필요. v2의 네 실적 요건은 참가자격 절이 아니라, 제안요청서의 기술능력평가 90점 중 정량평가 20점 → 사업실적 6점 배점표에서 확인됩니다. 저장된 네 행의 requirement_role은 모두 mandatory입니다.

실제 원문 평가표에는 “최근 3년 이내 학생 해외어학연수 등 사업이행 5천만원 이상 실적”과 “최근 3년간 실적(단일규모 5천만원 이상)”이 점수 구간(100%, 70~100%, 40~70%, 40% 미만)과 함께 나옵니다. 반면 별도의 “입찰참가 자격 및 조건” 절에 5천만 원 수행실적을 참가 필수 기준으로 요구한 문장은 확인되지 않았습니다.

따라서 현재 v2 분석으로 실적 5천만 원을 충족하지 않는 회사를 입찰 자격 미달로 확정하면 잘못될 위험이 있습니다. 평가 배점과 참가자격은 구분해야 하며, 기존 결과를 직접 변조하거나 테스트 Golden을 수정해서 해결하지 않습니다.

5. 검증 가능한 추가 사실과 제한

v1·v2 모두 전체 원문 첨부 4건을 추출했지만 분석 상태는 PARTIAL입니다. 문서 텍스트가 입력에서 잘렸다는 근거는 없었으며, 두 차수 모두 원문에 없는 업종 세부 표현이 구조화 검증에서 탈락했습니다. 특정 분석 실행의 후보 선택과 LLM 응답 차이가 최종 출력 차이에 관여했으나, 저장된 결과만으로 모델의 내부 생성 과정을 재구성할 수는 없습니다.

중소기업/소상공인 확인 등 복합 조건도 비정형 진단에 남아 있으며, 단순히 표준화된 요건 건수만으로 분석 완결을 선언해서는 안 됩니다. 평가표 오분류를 고친 뒤 여러 공고 Golden에서 실제 판정 영향과 회귀를 따로 검증해야 합니다.
