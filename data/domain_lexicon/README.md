## Dataset contract

- `seed.tsv`: *research hypotheses* for 50 distinct concept anchors; forms outside exact spelling/spacing are associated only as `RELATED_CANDIDATE`, **not synonyms**.
- `candidates-v0.1.json`: only corpus-observed expressions. Each record stores concept ID, preferred label, observed surface, relation type, domain, optional Requirement mapping candidate, `UNREVIEWED`, frequency, distinct notice count, version, at most two short source excerpts and unreviewed `context_role_candidate` hints (e.g. PAYMENT_OR_OPERATIONS versus QUALIFICATION), exact notice/round, extraction-file path, file SHA256, block SHA256, block index, and location. All records have `search_expansion_approved=false`.
- `auto-candidates-v0.1.json`: independently detected industry, certificate and staff expressions appearing in at least two distinct notice-round directories. `UNMAPPED_CANDIDATE`, not merged with concept seeds, and not production approved. False positives are expected.
- `relations-v0.1.json`: separate candidate concept relationships. `NOT_EQUIVALENT` guards prevent conflating, for example, headquarters location with place of business or registration with certification. `BROADER_THAN_CANDIDATE` is **not** a verified legal hierarchy.
- All unobserved seed expressions are omitted from grounded records; no model-generated source is presented as an actual occurrence. No raw attachment or full document is copied into the generated outputs.

## Reproduction / integrity check

From repo root, with Python 3.11+:

```powershell
py tools/domain_lexicon/build.py
py tools/domain_lexicon/discover.py
py tools/domain_lexicon/validate.py
py -m pytest tools/domain_lexicon/test_lexicon.py -q
```

Limit read scope for an initial smoke: `py tools/domain_lexicon/build.py --max-files 10 --out smoke.json` (do not commit temporary smoke files).

Snapshot as of this PR: **124 notice-round directories, 277 extraction documents, 49,812 blocks, 271 distinct extraction file SHA256 values; 50 grounded concept anchors / 123 expression records; 38 independent auto-discovery candidates.** Every candidate remains UNREVIEWED. Duplicated extraction SHA across notice-rounds are not silently treated as separate *unique source documents*, although occurrences still record the actual notice and round.

## Search evaluation gate

The existing E3 Document QA 60-case draft fixture and evidence labels can form a *future* retrieval baseline, but only when its matching per-version index is available and independently frozen. Existing historical baseline results must not be attributed to the new lexicon. At present: **Recall@K delta = not measured; false-source rate = not measured; latency delta = not measured.** There is no deployment recommendation. Approved synonyms must be human-reviewed, versioned, and re-evaluated for wrong evidence, same-notice version isolation, and runtime cost before a separate MASTER integration request.

1. Domain reviewer verifies each auto-derived term, each relation, and ambiguous company-size, region, industry registration, and scope expressions.
2. Check actual AWS RDS/S3 extraction evidence via separately authorized bounded read-only access; update source provenance only after hashing and confirming original revision keys.
3. Run frozen per-version retrieval comparison with baseline, spacing-only normalization, **human-reviewed** synonym expansion, and context-aware alternatives. Report Recall@K, false evidence, latency together.
4. MASTER may integrate a *new* opt-in search adapter only after approval; Rule Engine and canonical code masters remain unchanged.
